1. Executive overview

ecm-loadtest is a single-binary Rust CLI for load testing the ECM Image Viewer Service, the legacy PDF servlet it replaces, and the EWS file-drop ingestion pipeline that feeds the ECM platform. The tool produces per-service, per-rate-level, per-run CSV samples, summary JSON, and HTML reports, plus cross-service comparison reports for head-to-head analysis.

3. Configuration

YAML config has two levels: top-level run settings, and a services: list. Each enabled service runs concurrently.

pattern: "rate_levels"
rate_levels:
  rates: [5, 25, 50, 100]
  duration_seconds: 60
  runs_per_rate: 3
  cooldown_seconds: 30
  apdex_threshold_ms: 500

services:
  - name: "ecm-image-viewer-service"
    enabled: true
    mode: "online"
    template: "pdf-retrieval-service"
    host: "https://ecm-idev1.example.gov"
    endpoint: "/ecmimageviewer/documents/view"
    method: "POST"
    body_template: '{"dcn":"${dcn}","pages":${pages}}'
    manifest:
      path: "examples/manifest.csv"
      selection: "random"

Template inheritance

Each service references a template via template: <name>. The loader resolves templates/<name>.yaml and deep-merges: service block fields win; template fields fill the gaps. Templates may extend via extends: <parent-template>. Circular extends fails at startup with CONFIG-CONFLICT (exit 12).

Substitution syntax

${dcn}DCN column from the current manifest row
${pages}Manifest pages cell, fallback to default_pages
${env}Resolved environment label
${<col>}Any column from the manifest row

4. Execution flows

Online request lifecycle (TTFB seam)

The TTFB seam sits at the instant .send().await returns, BEFORE any body bytes are consumed. ttfb_us, transfer_us, and total_us are recorded into three independent HDR histograms. Per-request invariant: total_us == ttfb_us + transfer_us within clock granularity.

Batch lifecycle (local transport)

XML is uploaded BEFORE PDF: ECM batch services watch for the PDF arrival as the trigger, so uploading PDF first risks the service picking up an incomplete pair. T0 is recorded the instant the second (.pdf) write completes. T1 is the moment the watcher detects pickup; T2 (optional) is the completion log marker.

7. Error handling

Every fallible operation is either ?-propagated with an anyhow::Context message or matched and classified into one of the documented categories. Nothing is swallowed; nothing panics in production paths. Each error category maps to a fixed exit code (see section 11).

Per-request errors (timeout, connect, tls, status_4xx, status_5xx, body_too_small, body_too_large, bad_magic_bytes, other) are recorded into the sample CSV and aggregated into summary.errors but do not abort the run. When the same category exceeds 100 occurrences in a 10-second window, logging switches to once-per-100 plus a per-minute WARN summary so a flapping target cannot fill a multi-GB log file.

8. Extension points

Add a new service mode

  1. src/templates.rs: add the new variant to the Mode enum.
  2. src/main.rs in run_command: route the new mode to its own module function.
  3. Write the new module (model on loadtest.rs for online, batch.rs for file-drop).
  4. Add a YAML template under templates/ with the new mode: value.

Add a new metric

  1. Extend ServiceSummary in src/report.rs with the new field.
  2. Compute the metric in src/loadtest.rs::finalize_summary or src/batch.rs::execute_cycle.
  3. Surface it in src/report.rs::build_service_html (KPI card and/or table row).
  4. Add it to the rate/volume aggregate in write_rate_aggregate if it should roll up.

Add a new HTML report section

The format string at the end of build_service_html is the single source of truth for section ordering. Insert the new <h2> and helper output in the position it should render, then add the section name to the post-validation HTML integrity test in src/report.rs::post_validate.

10. CLI reference

ecm-loadtest run --config PATH [options]
  --out-dir DIR              override output dir from YAML
  --no-archive               skip pre-run archive rotation
  --no-serve                 don't start the embedded server
  --no-launch                start server but skip browser open
  --port N                   embedded server port (default 8765)
  --vscode                   open reports in VS Code instead of browser
  --launch-only-compare      open just the compare URL for multi-service runs
  --env LABEL                override every service's environment field
  --no-report                skip per-run HTML, keep compare + aggregates
  --stop-at-error-pct PCT    override YAML circuit breaker
  --target-rps N             single-rate ad-hoc run
  --skip-post-validation     skip the 8-group post-run validation suite

ecm-loadtest report --run-id TS [--out-dir DIR]
ecm-loadtest serve  [--out-dir DIR] [--port N]
ecm-loadtest tui    [--config PATH] [--out-dir DIR]
ecm-loadtest docs   [--out-path PATH]
ecm-loadtest example-config

  --verbose      enable DEBUG
  --quiet        suppress INFO
  --log-file P   tee log output to a file

12. Glossary

AC1-AC4Acceptance criteria 1 through 4 of the comparison user story.
ApdexApplication Performance Index. T = satisfied threshold; 4T = tolerating boundary.
DCNDocument Control Number. Primary identifier for any document in ECM.
E4931Documented ECM batch race condition: EWS queries the ECM database before the ingestion service's commit completes.
ECMEnterprise Content Management. The platform this tool exercises.
EWSEnterprise Web Services. The upstream batch pipeline that feeds ECM.
idevIntegration development environment label. ITEST is the next tier up.
STP / TLM / CCI / DCOriginating systems that POST to the ECM Image Viewer Service.
TTFBTime To First Byte. From request start to the instant response headers arrive.
